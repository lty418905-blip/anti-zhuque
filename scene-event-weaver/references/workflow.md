# Scene-specific event-library workflow

## 1. Evidence first

Read the actual scene, outline, or article. Record source locations for every scene anchor. If only a premise is available, state that the library is premise-level and cannot preserve unstated facts.

For fiction, freeze events, choices, causal outcomes, character knowledge, relationship stage, point of view, time, place, object state, setting rules, and exit interface.

For narrative nonfiction, split material into verified facts and optional presentation choices. Never create an incident, quote, reaction, or consequence that is not supported by the user or a reliable source.

## 2. Describe the missing function

Name the actual need before generating events:

- `PACING_RELEASE`: reduce sustained heaviness without erasing consequences.
- `EMOTION_VISIBILITY`: make emotion visible through behavior rather than explanation.
- `RELATION_FRICTION`: reveal distance, trust, embarrassment, or unequal goals.
- `WORLD_ACTIVITY`: let other people and the environment pursue their own business.
- `BODY_OR_OBJECT_PRESSURE`: give thought and dialogue a physical constraint.
- `DECISION_COST`: make a choice consume time, attention, face, resources, or comfort.
- `HUMOR_FROM_MISMATCH`: allow plans, manners, timing, or competence to collide.
- `TRANSITION`: carry residue from one scene or paragraph into another.

If no function is missing, select no event.

## 3. Build candidates from the current scene

Use the seed library to broaden mechanisms. Do not rename a seed and call that adaptation. Each candidate must combine at least two current-scene anchors, such as an existing object and a character's immediate goal, or a time window and a relationship boundary.

Good candidates contain a possible visible trigger, a character-owned immediate need, two or more reaction branches, a current cost, a residue window, a point-of-view gate, forbidden outcomes, and at least two variation axes.

Reject pseudo-events that are only mood, symbolism, exposition, a generic gesture, or a restatement of a planned plot beat.

## 4. Score without pretending to be objective

Use 0–2 only as a comparison aid for scene fit, character fit, causal fit, tone fit, downstream residue, point-of-view visibility, and non-repetition. A hard conflict overrides the total. Do not publish a score as literary truth.

## 5. Select and compress

Default to zero to five selected events. Prefer the smallest set that changes the scene's behavior. Several decorative events are weaker than one event with a clear aftereffect.

Send only the selected call card to a writer. Keep rejected alternatives, scoring language, and seed IDs out of prose prompts unless the user explicitly wants an editorial appendix.

## 6. Aftereffect window

Every selected event declares `NEXT_ACTION`, `REST_OF_SCENE`, `REST_OF_CHAPTER`, or `CROSS_SCENE`. At least one later action, answer, route, object state, or interaction must reflect the residue. Pure texture may use `NEXT_ACTION`, but an entire chapter cannot consist only of texture that resets instantly.

## 7. Escalation

Return to outline or user review if a candidate changes a major event or outcome, a character's choice or knowledge, a relationship stage or promise, a timeline or ownership fact, a scientific or safety claim, or the scene exit interface.
